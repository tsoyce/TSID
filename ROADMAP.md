# §1. Принципы развития

Пять фильтров. Фича, не проходящая хотя бы один, — не делается или переделывается.

1. **Опциональность.** Ни одно ограничение не включается принудительно. Новая политика =
   выключенный по умолчанию тумблер в `/admin/settings`. Пароль, 2FA, срок сессии, требования
   к полям — всё настраивается, всё можно отключить.
2. **Тридцать секунд.** Любое пользовательское действие укладывается в полминуты. Новый экран
   с формой на 8 полей — повод для спора, а не для реализации. Мастера дробятся и предзаполняются.
3. **Ноль зависимостей.** Не появляется Composer/node в проде. Новая библиотека либо вендорится
   одним файлом, либо пишется своя на 100–300 строк (как Jwt, WebAuthn, Cbor).
4. **White-label по умолчанию.** Ни одной новой строки с зашитым названием установки: всё через
   `Setting::appName()` и `{{APP_NAME}}`. Новые визуальные элементы наследуют `--ink`.
5. **Проверяемость.** Каждый эпик приносит свои автопроверки. Релиз не выпускается, пока
   вся батарея не зелёная. Отдельно проверяется ПРОВОДКА (`tools/wiring_audit.php`):
   каталог, обещающий переключатель, обязан быть подключён к коду. Дефект этого
   жанра прожил в проекте два года и не был виден ни одной другой проверкой. Цель — держать покрытие не ниже 1 проверки на 100 строк кода.

## Один интерфейс настроек: три шага

Ревизия v4.9 (`tools/settings_audit.php`) показала, что мёртвых настроек нет —
65 ключей, 53 настраиваются. Беда была в другом: настройки лежали в шести
местах. Сведение идёт шагами, потому что «переписать всё разом» здесь означает
переписать шесть рабочих экранов одновременно.

| Шаг | Что | Состояние |
|---|---|---|
| 1 | Указатель разделов + слой полей (объявление вместо разметки) + реквизиты | **сделано** (v4.9) |
| 2 | Разделы въезжают внутрь одного экрана боковой колонкой вместо ссылок наружу; вкладки настроек становятся такими же разделами | **сделано** (v4.10) |
| 3 | Все существующие поля переводятся на слой полей; маски там, где формат известен | **закрыт** (v4.13.1): все формы на объявленных полях. Осталось 13 мест одного жанра — поле и кнопка в одну строку, где подпись стоит над парой |

Почему не разом: шаг 2 меняет адреса экранов, шаг 3 трогает каждую форму
проекта. Вместе это одна правка на полторы тысячи строк без единой точки
возврата — а по шагам каждая проверяется батареей отдельно.

# §4. Что осознанно НЕ делаем

Чтобы не возвращаться к этим спорам (в духе §15 архитектуры):

| Идея | Почему нет |
|---|---|
| SPA-переписывание фронта | SSR + точечный JS работает, интерактива на 5% страниц; SPA = два деплоя, CORS, токены в браузере |
| Composer в проде | Одна из главных ценностей — «залил на хостинг и работает» |
| Микросервисы, очереди (Redis/RabbitMQ) | Масштаб не тот; MySQL-очередь с ретраями уже есть и проверена |
| SAML | Другая вселенная XML-подписей ради интеграции с legacy-корпоративом, которого у нас нет |
| Биометрия «своя» | Passkeys уже дают биометрию средствами ОС — правильнее и безопаснее |
| Массовые действия над пользователями | Намеренно нет (§5.2 архитектуры): «от греха» |
| Хранение паролей порталов | Порталы паролей не видят и не хранят — это фундамент |
| Собственный протокол вместо OIDC | Стандарт аудирован и известен нейросетям — на этом держится генерация `integration.md` |
| CSS оформления от портала | Позволяет спрятать логотип SSO и нарисовать поверх формы что угодно — готовый инструмент фишинга. Вместо разметки портал передаёт параметры, см. [PORTAL_PROTOCOL.md](PORTAL_PROTOCOL.md) |

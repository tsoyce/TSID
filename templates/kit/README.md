# PHP-kit подключения к {{APP_NAME}} — {{CLIENT_NAME}}

Минимальная рабочая интеграция «из коробки».

## Установка — два шага

1. Положите каталог `sso/` в **веб-корень** сайта {{CLIENT_URL}} (тот каталог,
   на который смотрит `DocumentRoot`; для раскладки `app/ + public/` это
   `public/`). Проверка: `{{CLIENT_URL}}/sso/install.php` открывается.
2. Откройте **ссылку установки** из карточки портала.

Реквизиты, ключ переноса и адреса приедут сами и лягут в файл вне веб-корня;
установщик тут же проверит связь и покажет, что не так. Вписывать в
`config.php` ничего не нужно — плейсхолдеры в нём это нормально.

После установки удалите `sso/install.php`. Дальше секрет клиента, ключ переноса и
проверка связи — на экране настроек `{{CLIENT_URL}}/sso/admin.php`.

## Файлы

| Файл | Роль |
|---|---|
| `install.php` | установщик: забирает реквизиты по одноразовой ссылке и проверяет связь |
| `bootstrap.php` | одна точка доступа к конфигу, секреты вне веб-корня, сессия вашего приложения |
| `config.php` | issuer, client_id, redirect_uri, `allow_local_login`. Секреты — не здесь |
| `SsoClient.php` | весь протокол: PKCE, обмен кода, проверка id_token по JWKS, userinfo, refresh |
| `login.php` | старт входа (и JSON-endpoint для popup-виджета) |
| `callback.php` | приём кода, проверка, локальная сессия. **Матчинг только по sub!** |
| `logout.php` | локальный выход + передача на SSO |
| `backchannel.php` | приём событий SSO: logout, user.blocked, user.deleted, user.restored… Сессии человека гасит сам |
| `hooks.php` | **что портал делает по этим событиям** — единственный файл, который надо дописать по-настоящему |
| `widget.php` | include-сниппет: кнопка входа или аватар+меню |
| `admin.php` | **экран настроек SSO**: секрет клиента, ключ переноса, проверка связи. Только администратору портала; из консоли — `php sso/admin.php check` |
| `checks.php` | проверка связи — одна на экран, установщик и консоль |
| `sso-button.css` | готовая кнопка входа и виджет, цвета уже подставлены |
| `sso-widget.js` | поведение меню виджета: отдельным файлом ради строгого CSP |
| `users.php` | выгрузка ваших людей для переноса в SSO |
| `fedcm.php`, `fedcm-finish.php` | вход без редиректа там, где браузер это умеет |
| `migration.sql.example` | требования к схеме, переведённые в DDL |

## Куда вписать свою логику

1. `bootstrap.php` — функция `sso_session_start()`: подключите бутстрап своего
   приложения, если у сайта своя сессия. Иначе вход окажется в чужой сессии, и
   это не даст никакой ошибки — просто «вошёл, но я гость».
2. `callback.php` — блок `TODO`: find-or-create вашего пользователя по `sub`.
3. `hooks.php` — `sso_on_user_gone()`: отключить у себя человека, удалённого или
   заблокированного в SSO, и `sso_on_user_restored()` — включить того, кто
   отменил удаление. Что делать с данными, говорит `$payload['mode']`: при
   `scheduled` ничего не стирать, при `final` и `purged` — стереть (подробно —
   integration.md §5). Сессии мост гасит сам. **Пока это заглушка, удалённый в
   SSO человек продолжает жить у вас.** Необработанное событие не теряется — оно
   ложится в `var/sso-events.ndjson`, и проверка связи на экране настроек про
   него скажет.
4. `users.php` — функция `sso_export_users()`: запрос к вашей таблице
   пользователей. Только если переносите существующую базу.
5. `hooks.php` — `sso_is_admin()`: кто открывает экран настроек `sso/admin.php`.
   По умолчанию — уровень 70 в SSO или владелец установки; своя проверка
   администратора — сюда.

Больше нигде дописывать не нужно. Конфиг спрашивайте **только** через
`sso_config()`, а «показывать ли кнопку входа» — через `sso_ready()`: иначе
однажды получится кнопка, которая на нажатие отвечает «вход не настроен».

## Четыре вопроса, которые возникают у всех

Ответы — в `integration.md`, раздел 0, первым же экраном. Коротко:

- Свою форму входа по паролю — **убрать**, оставив за флагом
  `allow_local_login` (по умолчанию `false`).
- Администратора узнавать по `roles`, а без карты ролей — по
  `access_level >= 70`.
- Человеку без прав — завести запись и отдать 403 в админке; «пускать ли
  вообще» решает SSO, а не вы.
- Старые аккаунты связывать по подтверждённой почте; по логину — только когда
  почты нет ни с одной стороны.

Полная спецификация — `integration.md` рядом (её можно целиком отдать нейросети).

## Требования

PHP 8.0+, расширения curl и openssl, запись в `sso/var/` (кэш JWKS и sid-реестр).
`redirect_uri` должен побайтово совпадать с зарегистрированным: `{{REDIRECT_URI}}`.

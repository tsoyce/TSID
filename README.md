# Самостоятельный SSO-сервер на PHP

[![CI](https://github.com/OWNER/REPO/actions/workflows/ci.yml/badge.svg)](https://github.com/OWNER/REPO/actions/workflows/ci.yml)
[![License: MIT](https://img.shields.io/badge/license-MIT-blue.svg)](LICENSE)
![PHP 8.2+](https://img.shields.io/badge/PHP-8.2%E2%80%938.4-777bb4)
![Без зависимостей](https://img.shields.io/badge/composer-не%20нужен-success)

Открытый OpenID-провайдер для сети сайтов: один аккаунт, один профиль, одна админка.
Ставится на обычный shared-хостинг за три минуты, без Composer и node. Полностью
**white-label**: название, логотип, favicon, цвет и подвал меняются из админки —
Название установки задаётся при установке и в настройках — в коде оно не зашито.

*Self-hosted PHP OpenID Connect provider: PKCE, passkeys (WebAuthn), TOTP 2FA,
back-channel logout, admin panel, 3-minute web installer. No Composer, no node. MIT.*

Реализация архитектуры **v2.0** из [ARCHITECTURE.md](ARCHITECTURE.md) —
документ остаётся источником истины по протоколу и решениям. Планы развития — в
[ROADMAP.md](ROADMAP.md). Лицензия — [MIT](LICENSE).

## Что внутри

- **OAuth 2.0 Authorization Code + PKCE (S256)**, id_token RS256, discovery, JWKS,
  introspection, revocation, refresh-ротация с reuse-detection, back-channel события.
- **Инсталлятор** `/install`: 7 шагов от проверки окружения до суперадмина; после установки
  блокируется lock-файлом.
- **Мастер «подключить сервис за два клика»**: анкета → client_id + секрет (показывается один раз)
  → скачиваемые `integration.md` (спека для нейросети) и PHP-kit (референс-интеграция без Composer).
- **Профиль**: ID-карта с MRZ-строкой, аватары (GD → webp 512/128/32), 2FA (TOTP + 10 recovery-кодов),
  устройства, сервисы, смена email с кнопкой «это не я», удаление с холдом 14 дней.
- **Админка**: дашборд (KPI + SVG-график), пользователи с фильтрами, карточки с вкладками,
  имперсонизация (только superadmin, со следом в аудите), роли (§9: доступ ≠ роль),
  логи (аудит + CSV, ошибки, почта), настройки (брендинг/SMTP/политики/ключи/maintenance),
  здоровье, импорт пользователей из CSV/JSON с маппингом колонок.
- **Организации**: доступ к порталу выдаётся не человеку, а компании — участники получают
  его при первом входе, даже если портал открыт «только по приглашению». Claim `orgs` в id_token.
- **Экосистема**: соцвход (Telegram/Яндекс/VK/GitHub, все выключены по умолчанию),
  webhooks с HMAC-подписью и ретраями, Admin API v1 со scope-токенами и OpenAPI 3.1
  (включая право `*` — уровень суперадмина для программы: люди, порталы, роли,
  организации, доступы и настройки),
  **SCIM 2.0** для кадровых систем, которые умеют синхронизировать людей только им.
- **FedCM**: вход без ухода со страницы портала — браузер сам показывает нативный
  диалог выбора аккаунта. Дополняет OIDC: браузер без поддержки идёт обычным путём.
- **Профиль как источник правды**: девятизначный номер аккаунта с контрольной
  цифрой — его можно продиктовать в поддержку, в отличие от `sub`; галерея
  фотографий, куда попадает всё, что отдали соцсети при входе, — аватарку
  человек выбирает сам, автоматически она не меняется; имя, фамилия, дата
  рождения, телефон и пол забираются у провайдеров, но только в пустые поля.
- **Установка на домашний экран (PWA)**: манифест и иконки генерируются из настроек
  брендинга, поэтому у каждой инсталляции своё имя и свой знак. Service worker
  намеренно скупой — только версионированная статика; HTML, протокол и API идут
  мимо него, потому что на origin SSO кэш означал бы чужие данные в чужих руках.
  Без сети — своя заглушка с кнопкой, возвращающей на нужную страницу.
- **Кириллица**: слаги, домены и машиночитаемая зона ID-карты транслитерируются
  по правилам (BGN/PCGN для читаемого, ИКАО Doc 9303 для MRZ), а не выбрасываются.
- **Два языка (ru/en)** для всего интерфейса — и пользовательского, и админского. Язык берётся из переключателя, профиля,
  `ui_locales` портала или `Accept-Language`. Админка переведена целиком.
- **Наблюдаемость**: JSON-lines логи с request_id, синхронный аудит (словарь — Приложение C),
  `/status` (ok/degraded), метрики Prometheus на `/metrics?token=…`,
  cron-задачи §11.4 одной точкой входа.
- **Интерфейс**: собственная дизайн-система (SVG-иконки, тёмная тема, бенто-раскладка),
  командная палитра **Ctrl+K** для поиска по всему, onboarding-чеклист после установки,
  адаптив без горизонтального скролла от 320px. Акцент можно поставить любой:
  цвет надписи на кнопке и оттенок ссылок пересчитываются по контрасту WCAG,
  так что жёлтый или бирюзовый фирменный цвет не превращает интерфейс в нечитаемый.

## Требования

PHP 8.2+ (цель 8.3), расширения `pdo_mysql, openssl, mbstring, curl, json, gd` (+`sodium` желательно),
MySQL 8 / MariaDB 10.6+. Node и Composer **не нужны**: зависимости вендорены
(`lib/PHPMailer`, `public/assets/js/qrcode.js`), CSS написан руками на дизайн-токенах §10.

## Установка

1. Залейте проект на сервер, webroot → `public/` (сниппеты Apache/nginx — Приложение D
   и финальный экран инсталлятора).
2. Откройте сайт — попадёте в `/install`. Семь шагов, три минуты.
3. Повесьте cron: `* * * * * php /path/to/cron.php` (или `curl /cron?token=…`).
3a. **После обновления кода** примените миграции: кнопка в шапке админки,
   `/admin/migrate` или `php migrate.php` по SSH. Пока они не применены,
   разделы с новыми таблицами показывают предупреждение, а не ошибку.
4. Удалите каталог `/install` с сервера, включите 2FA — без неё админка не пустит.
5. Пройдитесь по чеклисту прода — Приложение E архитектуры.

## White-label: сделайте его своим

`/admin/settings` → Брендинг:

| Что | Как |
|---|---|
| Название | везде: шапка, письма, кнопка «Войти через …» в генерируемых китах |
| Логотип | загрузите картинку — впишется в шапку и экраны входа (прозрачность сохраняется) |
| Favicon | загрузите квадрат — сконвертируется в 64×64 |
| Акцентный цвет | одна CSS-переменная перекрашивает весь интерфейс |
| Подвал | свой текст вместо дефолтного |
| Cookie | имя задаётся в `config/config.php` → `session.name` |

## Подключение портала

`/admin/clients` → «Подключить сервис» → анкета → готово. Скачайте:

- **integration.md** — самодостаточная спека: скормите её нейросети («подключи по этой спецификации»),
  и она напишет интеграцию для любой платформы;
- **PHP-kit (.zip)** — рабочая интеграция из коробки: каталог `sso/` в корень портала,
  секрет в `config.php` — кнопка входа работает. Матчинг локального аккаунта — **только по `sub`**.

Секрет клиента показывается один раз; в файлах — плейсхолдер `{{CLIENT_SECRET}}`
(включение секрета в файлы — осознанный чекбокс). Setup-ссылка назначает первого
админа портала (`client_admin` — делегированная админка только своего портала).

## Разработка

```bash
# dev-сервер (sqlite вместо MySQL — только для разработки)
php -d extension=pdo_sqlite -d extension=sodium -S localhost:8710 -t public public/index.php
# пройдите /install, выбрав драйвер SQLite

# тесты — одна команда, серверы поднимаются и гасятся сами
bash tests/run-all.sh
#   линт → инсталлятор → юниты (RFC-векторы) → WebAuthn → e2e полного цикла →
#   состязательные к OIDC → смоук админки → Admin API → атомарность записей →
#   заглушка в корне → ревизии (контраст, словарь, схема) → мутации.
#   Числа не перечисляем: они устаревают быстрее, чем их правят. Прогон
#   печатает свои. Отдельные наборы — см. CONTRIBUTING.md
```

Почтовый транспорт `log` пишет письма в `storage/logs/mail/*.eml` — удобно для разработки.

В корне лежит `index.php` — заглушка, которая отвечает, если веб-сервер не переписывает адреса (не доехал `.htaccess`, запрещён `AllowOverride`, сайт стоит на nginx). Она называет причину по сочетанию признаков и, если каталог доступен на запись, предлагает кнопку: создаёт недостающие `.htaccess` из копии правил, которую носит в себе. Существующие файлы не трогает.

## Структура (§12)

```
public/          # единственный webroot: index.php + ассеты (css/js/шрифты)
app/Core/        # Router, DB, View, Auth, Jwt, Keys, Totp, Pkce, Crypto, Mailer, Audit…
app/Models/      # User, Client, SessionModel, RefreshToken, Access, Role…
app/Oidc/        # Discovery, AuthorizeFlow, TokenFlow, IdToken, EventDispatcher
app/Controllers/ # Auth, Registration, Oidc, Profile*, Admin/*
config/          # config.php (генерится инсталлятором) + installed.lock
storage/         # keys/ logs/ avatars/ cache/ — вне webroot
migrations/      # 001_init.sql … (префикс таблиц — плейсхолдером {users})
templates/       # layouts/ auth/ profile/ admin/ oauth/ errors/ emails/ kit/
install/         # инсталлятор; удаляется после установки
lib/PHPMailer/   # вендоренный PHPMailer (SMTP не пишем сами)
cron.php         # точка планировщика
```

## Отличия от архитектуры v2.0 (осознанные)

| Что | Почему |
|---|---|
| JWT RS256 своей реализацией (~100 строк на openssl), не firebase/php-jwt | без Composer в проде; alg захардкожен → alg-confusion невозможна по построению; RFC-векторы в tests/unit.php |
| CSS руками на токенах §10.3, без Tailwind CLI | тот же результат («собранный css коммитится»), минус node даже при разработке |
| Vanilla JS вместо Alpine.js | Alpine требует `unsafe-eval` в CSP — противоречит §8.3 (CSP с nonce); интерактива здесь на ~300 строк |
| PHPMailer вендорен файлами, не через Composer | тот же код, нет зависимости от composer на хостинге |
| SQLite-драйвер в DB-слое | только для локальной разработки и e2e-тестов; прод — MySQL |
| Схема §4 + 4 поля | `password_hash NULL` (импорт §13 без пароля), `one_time_tokens.user_id NULL` (setup-ссылка клиента), `clients.client_secret_old_*` (бесшовная ротация секрета), `user_client_access.consented_at` (память consent) |

Бэклог Phase 2/3 — §14 архитектуры: соцвход (таблица `linked_identities` уже ждёт),
passkeys, FedCM, инвайт-ссылки, i18n en.

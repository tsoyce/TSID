# Политика безопасности

SSO — сервер аутентификации: он держит пароли, ключи подписи и сессии всей
экосистемы. К сообщениям об уязвимостях относимся серьёзно.

## Куда сообщать

**Не открывайте публичный issue для уязвимости.** Используйте приватный канал:

- GitHub → вкладка **Security** → *Report a vulnerability* (Private vulnerability reporting);
- либо письмо мейнтейнеру, указанному в профиле репозитория.

Ответ — в течение 5 рабочих дней. Исправление критичных находок — приоритет над
любыми фичами; после выпуска патча вы получаете упоминание в CHANGELOG (если хотите).

## Что считается уязвимостью

- Обход аутентификации или второго фактора; вход под чужим аккаунтом.
- Подделка или неправильная проверка `id_token` / `access_token` / event-token.
- Обход PKCE, повторное использование authorization code, приём чужого `redirect_uri`.
- Open redirect через `redirect_uri` или `post_logout_redirect_uri`.
- SQL-инъекция, XSS, CSRF, SSRF, обход CSP.
- Эскалация привилегий: обычный пользователь → админ; `client_admin` → чужой портал.
- Утечка секретов: `client_secret`, TOTP-секрет, приватные ключи, токены в логах.
- Обход rate limit там, где он заявлен (§8.1 архитектуры).

## Что уязвимостью не считается

- Отсутствие HTTPS на инсталляции, развёрнутой без TLS (это ответственность администратора).
- Self-XSS, требующий вставки кода в консоль браузера самим пользователем.
- Отсутствие ограничений там, где они **намеренно опциональны**: минимальная длина
  пароля, обязательность 2FA (см. принцип опциональности в ROADMAP §1).
- Отчёты сканеров без подтверждённого сценария эксплуатации.
- Перебор на инсталляции с отключёнными администратором лимитами.

| Версия | Поддержка |
|---|---|
| 2.x | ✅ исправления безопасности |
| < 2.0 | ❌ |

## Для администраторов инсталляций

Перед выходом в прод пройдите чеклист — Приложение E архитектуры. Главное:
удалить каталог `/install`, закрыть `config/` и `storage/` по HTTP, включить HTTPS
и HSTS, настроить бэкап `storage/keys` (потеря ключей = все интеграции перестают
верить токенам), поставить cron. Раздел `/admin/health` покажет, что из этого не сделано.
